Challenges

The hard problems we had to solve before writing a single line of UI.

Identifying High-Value Mobile Use Cases
Not every desktop workflow belongs on mobile. The challenge was identifying the most valuable interactions for users on the move.
Preserving Enterprise Context
Enterprise workflows often contain significant complexity that is difficult to compress into mobile interfaces without losing meaning.
Supporting Operational Responsiveness
Users needed to respond quickly to approvals, notifications, and AI-generated events without the full desktop context.
Balancing Simplicity And Capability
The mobile experience needed to remain lightweight and fast while still supporting meaningful enterprise actions.
My Design Process

How I moved from ambiguity to a shipped, production-ready feature.

Discovery
Shadowed mobile enterprise users, studied field workflows, and identified where desktop-only access created the biggest gaps in operational continuity.
Use Case Prioritisation
Mapped which enterprise actions — approvals, alerts, AI responses, status checks — had the highest mobile urgency and lowest complexity to execute on small screens.
Interaction Design
Designed condensed mobile-first layouts for conversations, agent activity, and workflow monitoring — optimised for glanceability and one-handed use.
Notification Architecture
Defined a push notification model that surfaces only high-signal events — agent completions, escalations, and approvals — without overwhelming users with noise.
Offline & Sync Design
Designed state handling for intermittent connectivity — ensuring users could review and draft responses offline, with seamless sync when reconnected.
Validation & Iteration
Tested prototypes with field users in realistic mobile contexts, iterating on notification clarity, action speed, and information density until adoption friction was minimal.
My Solutions

Design decisions that turned each challenge into a capability.

Mobile-First Use Case Framework
Defined a tiered model separating mobile-native actions (approvals, alerts, quick responses) from desktop-required tasks (complex builds, deep configuration). Removed feature bloat and focused mobile on high-urgency interactions.
Adaptive Context Compression
Designed progressive disclosure patterns that surface essential context on mobile while preserving full depth on desktop. Users could act on summarised AI outputs without losing the thread of complex workflows.
Actionable Push Notifications
Built a smart notification layer that delivers AI-generated alerts with inline actions — approve, reject, reply, escalate — directly from the notification without opening the full app. Reduced response latency for time-sensitive enterprise events.
Offline-Ready Interaction Model
Designed a local-first state model that queues actions, drafts, and responses when offline, then syncs automatically on reconnection. Users stayed productive in low-connectivity environments without data loss.
Unified Cross-Device Continuity
Designed session handoff so users could start a conversation or workflow on desktop and continue it on mobile without losing state. AI context, agent activity, and thread history remained fully accessible across both surfaces.
Key Learnings

What designing this feature taught me about AI UX.

Mobile Scope Must Be Earned, Not Assumed
Not every enterprise feature belongs on mobile. The most valuable lesson was learning to say no — scoping mobile to actions where immediacy mattered most created a sharper, more trusted experience.
Notifications Are a Product Decision
Every push notification is a trust transaction. Over-notifying taught users to ignore the app; under-notifying made it feel useless. Getting signal-to-noise right was as important as the core feature itself.
Continuity Reduces Cognitive Load
When users could pick up exactly where they left off across devices, they made faster, more confident decisions. Cross-device continuity isn't a convenience — it's a core productivity feature.
Speed Is the Core Mobile UX
Mobile users tolerate no latency. Every interaction — loading a thread, approving a workflow, seeing an AI result — needed to feel instant. Performance is UX on mobile, not an engineering afterthought.
Offline Builds Confidence
Users in field environments trusted the app more once it worked offline. Designing for disconnection wasn't a fallback — it was a signal that the product was built for the real world, not just ideal conditions.
